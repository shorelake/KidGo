# KataGo Web 围棋工作台

基于现有 KataGo CUDA 可执行文件的 Web 服务，使用 Conda `go` 环境。
不需要重新编译引擎。默认模型从 `~/katago/models/` 选择非 Human SL 的 `.bin.gz` 文件。

## 启动

在 `cpp` 目录执行：

```bash
./run_web_svr.sh
```

默认监听 `0.0.0.0:3000`，本机访问 `http://127.0.0.1:3000`，其他设备访问
`http://服务器IP:3000`。启动脚本使用 `conda run -n go`，无需预先激活环境。
前台按 Ctrl+C 停止。首次启动自动生成 `web_service/data/access.token`，用其中的口令登录。
口令不会写到日志；可在本机查看：

```bash
cat web_service/data/access.token
```

端口被占用时会报错退出，不会终止已有服务。进程锁防止多个 Web worker 重复加载模型。
第一次启动如果没有前端构建产物，脚本会执行 `npm ci` 和 `npm run build`。
更新前端后执行 `KATAGO_BUILD_WEB=1 ./run_web_svr.sh`，或单独重新构建前端。

首次安装依赖（本机已完成）：

```bash
conda activate go
python -m pip install -r web_service/requirements.txt
cd web_service/frontend
npm ci
npm run build
```

可配置项：

| 环境变量 | 默认值 / 用途 |
| --- | --- |
| `KATAGO_HOST` | `0.0.0.0` |
| `KATAGO_PORT` | `3000` |
| `KATAGO_CONDA_ENV` | `go` |
| `CONDA_EXE` | Conda 可执行文件；未指定时尝试 `~/miniconda3/bin/conda` |
| `KATAGO_MODEL` | `~/katago/models/` 中非 human 模型；多模型时建议显式指定 |
| `KATAGO_BINARY` | `cpp/katago` |
| `KATAGO_CONFIG` | `web_service/analysis.cfg` |
| `KATAGO_DATA` | `web_service/data` |
| `KATAGO_WEB_TOKEN` | 指定访问口令，优先于自动生成的口令文件 |
| `KATAGO_SECURE_COOKIE` | HTTPS 部署时设置为 `1` |

例如：

```bash
KATAGO_MODEL="$HOME/katago/models/b10c512h8nbt3tflrs-fson-silu-rsnh.bin.gz" ./run_web_svr.sh
```

## 三阶段功能

1. **局面分析**：常驻 KataGo 子进程，HTTP 提交和取消任务，WebSocket 实时推送，断线时 HTTP 轮询恢复；推荐点、黑方胜率、预计目差、变化预览与归属图。
2. **练习、对弈与复盘**：5、7、9、11、13、15、19 路棋盘；两次点击确认落子、人机对弈、提示一手、悔棋、停一手、认输；左侧历史棋局导航、对局自动保存、逐手浏览、整盘分析、胜率和目差曲线、逐手注释；SGF 导入导出、SQLite 棋谱库与浏览器草稿恢复。
3. **运行保障**：访问口令、同源检查、会话隔离、登录限流、输入大小限制、分析队列限额、超时与取消、引擎崩溃自动重启、健康检查、单进程锁、systemd 与 Nginx 配置。

棋盘规则由 `sgfmill` 处理提子，再校验行棋顺序、禁入点和简单劫。
目前支持 KataGo `chinese` / `japanese` 两种规则，均对应简单劫；不把中国规则误当成 positional superko。

首次点击空点显示浅色虚线预览，第二次点击同一位置才落子；点击另一空点可移动预览，Esc 取消。
键盘 Enter/空格同样分两次确认。棋盘边距随尺寸调整，5 路等小棋盘的边角棋子不会被裁切。
AI 落子独立于变化预览，不会因为打开推荐变化而被丢弃；停一手会在当前手数旁明确显示。
AI 对弈采用五档强度：启蒙 32、入门 128、进阶 500、熟练 2000、挑战 6000 visits。前三档在有界目差损失内按权重选择候选，后两档始终采用引擎首选；停着仍由引擎首选触发。分析面板的搜索次数只控制局面/整盘分析，仍允许 1 visit。
5 路天元开局已确认可能被模型首选为 `pass`，并非坐标越界。为方便教学，5/7 路人机对弈在空盘开局、尚未停着且手数少于棋盘路数时，通过引擎 `avoidMoves` 排除当前一步的 `pass`；后续搜索仍可考虑停着。摆子局面、复盘分析和较大棋盘不受此策略影响。

### 儿童练习与音乐

新建棋局按模式、棋盘、名称排列，默认人机对弈。对弈以“练习1”、启蒙以“启蒙1”、复盘以“复盘1”分别递增编号（结合各自浏览器计数和历史名称）。切换模式会更新自动名称，手动名称保留；取消新建不占用编号，旧练习计数继续兼容。启蒙练习提供灯泡图标的落点提示。
贴目是计分时给白棋的补偿分，用来平衡黑棋先行优势，不是 AI 难度；界面标为“贴目（白棋补偿分）”。
AI 使用同一正式分析模型，五档强度属于练习档位，没有校准成真实段位。候选随机选择只能近似降低棋力，不能保证稳定的入门段位或各棋盘上强度严格单调；未来可接入专门的人类棋风模型并用对局测评标定。
吃子练习有五级：1 级净提子领先 3 子、2 级 5 子、3 级 7 子、4 级 13 子、5 级 21 子，新建默认 1 级。任一方首次达到目标即获胜并自动保存，双方停着但未达标则为和棋；不使用贴目。已保存的旧目标仍可读取。结果以 `B+Capture` / `W+Capture` 标识，终局注释记录目标及双方提子数。此结果是应用扩展，不是标准 SGF 胜因枚举。
确认落子后播放本地 Web Audio 合成的棋子落木棋盘“咔嚓”声：短促撞击噪声、轻微二次接触及木板衰减共鸣，不使用滑音（人类和 AI 均适用）；预览、停着、非法落点、复盘导航不播放。顶部音效按钮独立于背景音乐，静音偏好保存在浏览器；浏览器需要用户交互才能启用声音。
用户在吃子练习达标获胜，或在人机对弈确认计分获胜时，播放一次 5 秒的原创 C 大调胜利乐：明亮的八度上行旋律、鼓点与滚奏，以及结尾镲声和长和弦；败局、和棋和历史复盘不播放。播放期间背景音乐降至原音量的 20%，结束后恢复，后台切换或打开其他棋局会停止。音乐设置的“胜利音乐”开关独立控制，默认开启，偏好保存在浏览器。旋律由 Web Audio 本地合成，无外部采样或 API 调用。
背景音乐包括四首原创曲目：小小步伐、泡泡圆舞曲、阳光小路、棉花云朵，采用不同旋律、节拍与音色，92-116 BPM，无外部采样。
点击音符按钮开始/暂停播放，旁边的展开按钮可选曲、调整音量、切换单曲循环或随机切换，也可手动播放下一首。
随机模式在曲目结束后切换到另一首，避免连续重复；曲目、模式和音量会保留到下次打开页面。
背景音乐默认开启，初始音量 20%，最大 60%；页面切到后台会暂停。浏览器若阻止自动播放，会在首次点击或按键后自动开始；手动暂停会记住关闭偏好，刷新和其他操作不会擅自恢复。

资源：`frontend/public/music/*.wav`；曲目表为 `tracks.json`，授权说明在同目录 `LICENSE.txt`。
可用以下命令重新生成，然后重新构建前端：

```bash
python -m web_service.generate_music
```

### 棋谱与数据边界

- SGF 导入 UTF-8 主线、根节点摆子、贴目、规则、棋手、结果和注释；有旁支时会提示只导入主线。暂不支持中途摆子、其他棋盘尺寸或其他规则。
- SGF 导出不包含专用分析缓存，分析结果随棋谱保存在 SQLite。
- 对弈双方连续停着后自动打开终局计分。点击棋块标记或取消死子（淡色及叉号）；中国规则按子空、日本规则按地与提子，通过固定版本的 GoScorer 计算，白棋计入贴目。确认后保存最终结果和计分注释；也可取消最后两次停着继续下棋。认输直接结束。已保存的双方停着局面可从“终局计分”重新进入确认。
- 死子须人工确认，预计目差不是裁判结果。日本双活计分采用 GoScorer 的启发式判断，复杂死活争议应继续下棋解决，必要时可在棋谱信息填写正式结果。计分库版本与 MIT 许可证见 `vendor/`。
- 每个浏览器会话拥有独立棋谱库，使用相同访问口令也不会看到其他会话棋谱。当前不是多账号系统；清除 Cookie 或超过 30 天会话有效期后，旧棋谱不会自动归入新会话。重要棋谱请导出 SGF。
- 浏览器草稿保存在当前浏览器。练习/对弈中的落子会在空闲后自动保存到服务端，开始下一局前也会保存当前对局；复盘编辑仍可使用“保存棋谱”。左侧历史栏显示当前会话的服务端棋谱，支持搜索，点击默认显示最后一步。手机使用历史棋局按钮展开侧栏。
- 历史棋局仅选中项展开改名与删除图标；名称可写简短备注。删除需要确认，取消不会删除；删除当前棋局会清空当前工作区，避免自动保存重新创建已删除记录。
- 历史侧栏标题旁的向左收起图标可隐藏侧栏，工具栏“历史棋局”按钮重新展开；桌面收起偏好保存在浏览器。
- PC/Pad 保留原布局。宽度不超过 600px 的手机隐藏平铺的局势曲线和分析栏，底部“局势”“分析”按钮切换半透明浮层；浮层独立滚动并可收起，新建/打开棋局及切换对弈模式时默认收起。查看推荐变化时浮层自动收起以露出棋盘。
- 局面分析提供学习解读：优势方、胜率含义、推荐点的边线位置、双方参考应手及候选目差比较。它由已有搜索数据生成，不需要外部语言模型；棋理观察是学习方向，不代表已经验证的战术结论。
- 推荐属于当前局面的下一手行棋方：黑落子后推荐白，白落子后推荐黑。分析标题、胜率、目差和学习解读同步到该方视角；棋盘标明推荐方与下一手编号，候选以黑/白虚线外圈区分，内部编号表示推荐顺序。人机对弈和启蒙练习轮到用户时自动更新推荐，后台推荐分析可以被用户落子打断，不会自动弹出手机浮层。
- 局势曲线从第 1 手落子后的局面开始，不绘制初始局面；初始局面仍可通过第一手按钮或进度条回看。曲线固定使用黑方胜率和目差，避免逐手切换视角造成虚假的上下跳动；点击按 SVG 实际绘图坐标换算手数。
- 整盘分析后，“复盘重点”按同一局面中推荐着法与实战候选的预计目差排序，列出最多五项、至少 0.5 目的差距；点击回到落子前。缺少实战候选的手数不估算失分，显示实际比较覆盖率，重载棋局可从已保存分析重新生成解读。
- 自动保存和手动保存按顺序执行，切换棋局时不会把旧棋局的保存结果覆盖到新棋局。冲突更新返回 409，避免两个页面覆盖同一棋谱。
- 已完成分析任务暂存于内存，最多保留 64 个任务 / 4096 个局面或一小时；刷新恢复依赖草稿或已保存棋谱，未保存任务不会在服务重启后续跑。

## 运行与部署

`analysis.cfg` 默认使用 GPU 0，4 个并行分析槽、每槽 4 个搜索线程、batch 32。
每次请求最多 10000 visits，最多 1001 个分析手数；全局最多 16 个活动任务、2048 个待处理局面，每会话最多 2 个任务。
任务超时为 `min(1800, 120 + 5 * 局面数)` 秒；取消后等待引擎逐手确认，15 秒仍无响应会重启引擎。
后台持续读取 stdout/stderr，引擎日志写到服务标准错误，崩溃时标记在途任务失败并自动重启。

健康检查：

```bash
curl http://127.0.0.1:3000/api/health
```

模型加载完成返回 200 和 `ready:true`，加载中或恢复中返回 503。
同一 GPU 服务只启动一个 Web worker；不要添加 `--workers` 或用开发热重载运行正式模型。

用户级 systemd 模板在 `deploy/katago-web.service`，路径已按本机配置。
需要开机运行时，调整路径后安装到 `~/.config/systemd/user/` 并启用该 unit。
仓库提供配置，但不会自动修改系统服务、Nginx 或防火墙。
`deploy/nginx.conf` 提供 HTTP 和 WebSocket 反向代理；公网部署请配置 HTTPS，设置安全 Cookie，并按网络环境限制直接访问 3000 端口。

备份时先停止服务，再备份整个 `data/` 目录，包括 SQLite、会话签名密钥和访问口令。
这些文件已被 Git 忽略，口令和数据库文件权限为 600。

## 开发与验收

后端、前端构建：

```bash
conda activate go
python -m pytest web_service/tests -q
cd web_service/frontend
npm run build
npx playwright test
```

浏览器测试需要本地服务运行在 3000 端口，默认读取 `../data/access.token` 自动登录。
可设置 `KATAGO_TEST_URL` / `KATAGO_TEST_TOKEN` 验收其他实例。
测试优先使用本机缓存的 Chromium；没有浏览器时执行 `npx playwright install chromium`。
覆盖真实分析、对弈、SGF 往返、保存恢复、小棋盘、音乐和 320/390/1440 像素布局。
截图和跟踪存于 `frontend/test-results/`，不纳入 Git。

Vite 开发模式：在 `frontend` 执行 `npm run dev`，API 代理到 `127.0.0.1:3000`。

主要文件：

| 文件 | 职责 |
| --- | --- |
| `app.py` | HTTP、WebSocket、会话与访问控制 |
| `engine.py` | 引擎进程、请求路由、取消、超时与恢复 |
| `go.py` | 坐标、局面重放与合法性校验 |
| `records.py` | SGF 和 SQLite |
| `frontend/src/main.jsx` | 对弈与复盘状态、棋谱管理界面 |
| `frontend/src/Board.jsx` | 棋盘及分析落点绘制 |
| `frontend/src/Music.jsx` | 音乐播放与音量 |

API 文档可在服务启动后访问 `/docs`。原始分析结果的胜率、目差统一为黑方视角，前端局面分析按下一手行棋方转换显示。
